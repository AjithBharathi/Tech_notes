Core Concepts of Scalability
Scaling: The fundamental ability of a system to handle increased load by adding resources.
How Scalability is Calculated: Measuring performance metrics (throughput, latency, and resource utilization) as the workload grows.
Use Cases: Determining when a system actually needs to scale versus when it needs optimization.
Drivers of Scale
Growth in Features: How adding new functionality impacts system overhead and codebase maintainability.
Data Volume: Managing the storage and retrieval challenges as databases grow from gigabytes to petabytes.
Complexity: The architectural strain caused by interconnected services and dependencies.
Geographical Based Data: Handling latency and data sovereignty across different global regions.
Scaling Strategies
Vertical Scaling (Scaling Up): Increasing the power (CPU, RAM) of a single server.
Horizontal Scaling (Scaling Out): Adding more machines to the resource pool to share the load.
Infrastructure & Optimization
Load Balancing: Distributing incoming network traffic across a group of backend servers.
Caching: Storing frequently accessed data in high-speed memory to reduce database hits.
Content Delivery Network (CDN): Distributing static content via a network of servers located close to the users.
Advanced Architectures
Data Partitioning: Splitting a large database into smaller, more manageable parts (sharding).
Asynchronous Communication: Using message queues to decouple services and prevent bottlenecks.
Microservices Architecture: Breaking a monolithic application into small, independent services.
Auto-Scaling: Automatically adjusting the number of active resources based on real-time demand.
Multi-Region Deployment: Running applications in multiple data centers globally for high availability and disaster recovery.
